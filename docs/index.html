Mabu live system

Mabu is a small yellow tabletop social robot. The Android tablet runs reflexes (face tracking → eyes & neck, eyelids, blinks) and streams audio over WebRTC to a desktop "brain" that handles VAD, STT, LLM, and TTS as a single Pipecat pipeline. This is the reference for the HTTP surfaces and ADB hooks that let you observe and drive both sides.

The tablet ships an Android app (com.mabu.anima); the brain is a Python process on the PC (pc-brain/pipecat_bot.py) that also bundles a small control HTTP server. Both expose JSON over plain HTTP on the LAN — no auth, no TLS, trust model is "same Wi-Fi".

Device API tablet · :7862

Embedded HTTP server in the Android app. LAN-only, single-threaded accept, two-worker pool. Bound to 0.0.0.0 so anyone on the LAN can poll. Responses include Access-Control-Allow-Origin: * so a browser dashboard can call straight in.

GET/status
Full DeviceStats snapshot — frame timing, transport state, motor link, battery, heap. The HUD overlay on the tablet reads from the same struct, so what you see here matches what's painted top-left.

Motor telemetry

Last positions actually written to the head MCU (0–100 scale, -1 if never sent in this session). Mirrors the wire, so scripted blinks & resting poses show up here too — not just live tween output.

FieldTypeNotes
motor_eyelid_l / motor_eyelid_rfloatPer-side eyelid position. Unit 4 has inverted scale: 5 = open, 50 = half-closed.
motor_eyes_lr / motor_eyes_udfloatEye gaze X/Y target. 50 is centered.
motor_neck_rot / motor_neck_elev / motor_neck_tiltfloatNeck yaw / pitch / roll. 50 is resting pose.

ADB control intents

For driving the app from a dev host without touching the screen. Sent via adb shell am broadcast; all action strings are namespaced com.mabu.anima.*.

BROADCASTcom.mabu.anima.SAY
Inject text as the user — appended to the LLM context, triggers a bot turn. No mic needed.
adb shell am broadcast -a com.mabu.anima.SAY --es text "what time is it"
BROADCASTcom.mabu.anima.SPEAK
Speak literal text via TTS (no LLM round-trip). Useful for tests.
adb shell am broadcast -a com.mabu.anima.SPEAK --es text "hello there"
BROADCASTcom.mabu.anima.MODE
Switch reflex mode. See Reflex modes.
adb shell am broadcast -a com.mabu.anima.MODE --es name FOLLOW
BROADCASTcom.mabu.anima.STOP
Cancel any in-flight LLM stream and stop TTS playback.
adb shell am broadcast -a com.mabu.anima.STOP
BROADCASTcom.mabu.anima.CAM
Toggle video mode — hand the single Camera1 device between on-device ML Kit (reflexes) and the Pipecat SDK (outbound video to the brain). on=1 releases the camera for the SDK; on=0 returns it to ML Kit.
adb shell am broadcast -a com.mabu.anima.CAM --es on 1
Status Wiring is in place; outbound frames don't yet flow due to a CameraManager init quirk in the Pipecat Android SDK. See setVideoMode() in MainActivity.

Brain API PC · :7861

Embedded in the Pipecat bot process; reads/writes go through the live PersonaControl. Commands are queued and applied on the pipeline loop, so the API never races mid-frame.

GET/status
Active persona + voice state, including available personas and on-disk voice samples.
Example response 
{
  "active": "mabu",
  "voice": "default",
  "mode": "live",
  "personas": ["mabu", "pirate pete"],
  "voices": ["default", "kendrick", "captain"]
}
GET/personas
List of saved persona display names.
GET/voices
Voice-clone WAV samples in pc-brain/voices/, plus the built-in default.
POST/switch
Switch to a different persona live. Queued; takes effect on next pipeline tick.
curl -X POST http://brain:7861/switch \
  -H "Content-Type: application/json" \
  -d '{"name": "pirate pete"}'
POST/voice
Set the current persona's voice. Voice must be a known WAV name (see /voices) or default.
curl -X POST http://brain:7861/voice \
  -H "Content-Type: application/json" \
  -d '{"name": "kendrick"}'
POST/create
Create a new persona from a system prompt. Set activate: true to switch to it in the same call.
curl -X POST http://brain:7861/create \
  -H "Content-Type: application/json" \
  -d '{"name": "ada", "prompt": "You are Ada, ...", "activate": true}'

Pipecat WebRTC offer PC · :7860

The Pipecat runner serves both the dev test UI (browser mic) and the WebRTC offer endpoint that the Pipecat Android SDK posts to. The Android app's PipecatVoice handles negotiation; you typically don't call this directly.

POST/api/offer
Small-WebRTC SDP exchange. Body and response shape are defined by the Pipecat Small-WebRTC transport — see docs.pipecat.ai.

Data channel events

Once the WebRTC session is up, the brain and device exchange JSON messages on the RTVI data channel. The device exposes them via PipecatVoice.Listener.onServerMessage(Value).

DirectionTypeUse
brain → deviceuser-started-speakingVAD detected user voice onset.
brain → deviceuser-stopped-speakingUser voice offset; turn may end.
brain → deviceuser-transcriptionStreaming or final STT result.
brain → devicebot-started-speakingTTS playback began. Echo-guard mute window starts.
brain → devicebot-stopped-speakingTTS playback finished.
device → braintrackStatusOutbound mic/cam track toggle (e.g. after SAY while muted).

Reflex modes

The four behavior presets the Android app's eyes-and-neck loop runs under. Set via the MODE ADB broadcast or by tapping the camera preview to cycle.

ModeBehavior
FOLLOWTrack the user's face with eyes + neck; spontaneous blinks + microsaccades + glances. Default conversational pose.
PUPPETMirror the user — eyes follow their gaze, eyelids mirror per-side blink, neck mirrors head pose.
IDLENo face-driven motion; saccades + blinks still run. Useful for "looking around" demos.
SLEEPEyelids closed, neck centered, no saccades. Quietest default for audio-only development.
